# LumiTag

> 一个基于 NB-IoT、GNSS 和墨水屏的低功耗定位标签，面向儿童安全与日常守护场景。

[English README](./README.md)

## 项目简介

**LumiTag** 是一个开源便携式定位标签项目，基于 **ESP32**、**NB-IoT**、**GNSS** 和 **1.54 英寸墨水屏**构建。

这个项目最初来自一个很朴素的想法：
做一个可以给孩子随身携带、放进书包，或者挂在日常物品上的小型定位设备。

它不是智能手表，也不是手机替代品。

LumiTag 更关注一件事：

> 用尽可能低的功耗，显示简单安全状态，并周期性上报位置。

## 为什么做 LumiTag？

很多定位设备存在几个问题：

* 体积偏大
* 功耗较高
* 完全依赖手机 App
* 硬件和固件封闭
* 交互复杂，不适合儿童长期携带

LumiTag 想探索另一种方向：

* 原型阶段优先使用 Wi-Fi，NB-IoT 作为后续低功耗广域网接入
* 使用 NB-IoT 实现低功耗蜂窝通信
* 使用 GNSS 获取位置
* 使用墨水屏显示常驻状态
* UI 极简，不做复杂交互
* 硬件和固件尽量开放
* 形态更接近标签、挂牌或小型安全徽章

目标不是做一个儿童手表。
目标是做一个安静、可靠、低功耗的安全标签。

## 核心功能

* 基于 ESP32 的固件
* Wi-Fi 原型网络接入
* NB-IoT 蜂窝通信
* GNSS 定位
* 1.54 英寸 SPI 墨水屏
* Deep Sleep 低功耗模式
* 周期性位置上报
* 极简状态 UI
* 适合原型验证的硬件结构
* 后续可扩展为自定义 PCB 和外壳

当前原型硬件：

| 部件   | 说明                    |

| 蜂窝通信 | NB-IoT                |

## 显示界面

墨水屏用于显示简单状态信息。

示例 UI：

```text
LumiTag

安全

学校

电量 82%

09:42 更新
```

墨水屏不用于显示地图或复杂界面。
它只显示最关键的信息：

* 安全状态
* 当前区域
* 电量
* 信号状态
* 最后更新时间

## 固件方向

第一版建议使用：

* PlatformIO
* Arduino framework for ESP32
* 模块化 C++ 结构

建议固件目录：

```text
firmware/
├── platformio.ini
├── src/
│   ├── main.cpp
│   ├── Display.cpp
│   ├── Display.h
│   ├── Location.cpp
│   ├── Location.h
│   ├── Cellular.cpp
│   ├── Cellular.h
│   ├── Power.cpp
│   └── Power.h
└── include/
```

原型阶段使用 Arduino 框架，是因为 ESP32、墨水屏、GNSS 解析、基础网络通信都有成熟库，开发效率更高。

后续如果需要更精细的功耗控制，可以逐步迁移部分代码到 ESP-IDF。

## 硬件接线

墨水屏通过 SPI 接口连接。

典型引脚：

| 墨水屏引脚 | ESP32 功能 |
| ----- | -------- |
| VCC   | 3.3V     |
| GND   | GND      |
| DIN   | MOSI     |
| CLK   | SCK      |
| CS    | GPIO     |
| DC    | GPIO     |
| RST   | GPIO     |
| BUSY  | GPIO     |

实际 GPIO 分配需要根据开发板可用引脚、NB-IoT 模块、GNSS 模块占用情况调整。

## 功耗策略

LumiTag 不应该让所有模块一直运行。

典型工作周期：

```text
唤醒
→ 获取定位
→ 通过 NB-IoT 上报位置
→ 必要时刷新墨水屏
→ 进入 Deep Sleep
```

设备设计应优先考虑：

* 降低唤醒频率
* 缩短 GNSS 工作时间
* 周期性或批量上报位置
* 尽量减少墨水屏刷新次数
* 尽可能长时间进入 Deep Sleep

## 产品形态

LumiTag 更适合做成标签类设备，而不是手表。

可能形态包括：

* 书包挂牌
* 儿童安全徽章
* 小型定位挂件
* 资产定位标签
* 老人安全标签
* 宠物或行李定位标签

第一版原型体积可以比最终产品更大。
如果要做成更精致的产品形态，后续需要自定义 PCB 和外壳设计。

## 项目状态

LumiTag 目前处于早期原型阶段。

当前重点是：

1. 硬件接线
2. Wi-Fi 连通性与云端接口
3. 墨水屏点亮
4. GNSS 定位
5. NB-IoT 卡恢复后的蜂窝通信
6. 功耗测试

## 当前网络策略

在 NB-IoT 卡恢复前，原型先使用 ESP32 的 2.4 GHz Wi-Fi 完成网络接入和云端流程开发。阿里云物联网平台已建立 `LumiTag` 产品与 `LumiTag_ESP32_01` 原型设备；`firmware/LumiTagWiFi` 提供不落盘凭据的串口交互式 MQTT 连通性测试，使用方式见 [固件说明](firmware/README.md)。
