# Design

## Context
现有固件已完成 GNSS 诊断和 Wi-Fi TLS MQTT 原型，尚无 Wi-Fi 定位服务权限或密钥；先前 GNSS 变更仍未完成。

## Goals / Non-Goals
**Goals:** 收集必要无线观测并在明确服务和质量后实现联网定位。
**Non-Goals:** 自动开通计费、创建云资源、存储完整位置历史或实现移动网络。

## Decisions
- 第一阶段仅扫描，接入点标识和信号只在内存中保留，不打印、不持久化、不向外发送；诊断显示数量。扫描按需启动，失败即清空旧数据。
- 中国大陆首选评估高德智能硬件定位和现有阿里云物联网辅助定位；前者官方说明仅企业开发者开放，后者现有实例可用性与收费待只读核实。Google 需要计费且当地覆盖可达性未验证。均不自动开通或调用。
- 根据用户 2026-11-19 明确要求，允许上报阿里云精度未知的 Wi-Fi 估算位置：只接受合法坐标、WGS-84 或 GCJ-02、有效 UTC 和扫描开始后不超过 60 秒的本次结果；明确 accuracyM 为 null、accuracyStatus 为 unknown、source 为 wifi，绝不将其标为精确定位或符合 GNSS 质量门槛。
- 真实请求前核实权限、数据传输范围、费用及用户授权。当前禁止公网 IP 回退；Wi-Fi 扫描不等于设备在外有网络。
- MQTT 对 Wi-Fi 位置的扩展依赖尚在进行中的 GNSS 变更，必须先协调原有仅 GNSS 的要求，避免两个变更产生矛盾。
- Wi-Fi 上报命令以单次请求获取当前结果，失败即丢弃，不缓存、不回退 IP；发布前后确认 MQTT 仍连接。设备不输出位置或指纹到串口日志，TLS、时间回退及 GNSS 逻辑保持原样。

## Risks / Trade-offs
- [室内接入点数据库覆盖或精度不足] → 家、学校等地点分别实测并保留失败状态。
- [扫描会影响 ESP32 Wi-Fi 会话] → 限定同步扫描时长并实机测试 MQTT 连通性。
- [凭据和 Wi-Fi 指纹敏感] → 用户现已明确要求设备保存配置，允许在手动执行保存时将 Wi-Fi 与云设备凭据写入设备 NVS；不写源码、文档、Git 或日志。未确认硬件加密，无法防止物理读取；不启用不可逆硬件安全配置。Wi-Fi 指纹不持久化。
- 凭据使用独立 NVS 项整体保存并读回核对，启动时仅加载完整合法数据并尝试连接；不自动发布定位。设备重新烧录应用时保留 NVS，不执行全片擦除。

## 2026-11-19 只读核查
- 上海现有公共实例在控制台显示已开通、测试环境，卡片包含实例 ID，规格显示在线设备上限 50、消息上下行 5 TPS。官方实例概述以卡片显示实例 ID 识别新版公共实例；固定规格内不计费，超额或其他服务仍须核对具体计费规则。
- 物联网平台“增值服务”已开通列表仅显示事件响应服务，未显示设备位置服务；增值服务目录未见定位项目。不能仅凭此完全排除后台历史权益，最终以阿里云客服或实际权限为准。
- 官方设备位置服务说明（2026-04-24 更新）称该服务为免费增值服务，仅已免费开通用户可使用，不再支持新开通。位置服务流程会保存设备物模型经纬度；未经用户对该数据写入和上传授权，不调用真实定位接口。
- LumiTag 产品“功能定义”的已发布版本显示为空，未见 GeoLocation 属性；未检查是否有草稿属性，不代表服务权限状态。
- 根据用户要求增加一次性实机诊断：设备在内存扫描热点并经 CA 校验的 HTTPS 向现有阿里云设备位置服务请求；串口只显示数量和状态，不输出热点标识、密钥或坐标。该请求可能写入设备位置属性；它不创建原始 payload 存储链路，不等同 Wi-Fi 位置质量验收或 MQTT 上报。扫描无法识别移动热点，用户应尽量关闭附近移动热点。
- 在用户明确要求下新增独立的私密显示命令：仅在操作者本机串口显示该次坐标以便人工核对，不落盘、不输出设备日志或 MQTT，不向聊天提供坐标。默认诊断仍隐藏坐标。阿里云响应未提供精度半径，不得把人工比对误差作为接口质量保证。
- 现有 Wi-Fi 扫描命令只显示本地计数，不采集或上传可用的指纹请求，也不等于完成 Wi-Fi 地理定位。无服务认证、覆盖、精度及收费实测证据。
- 官方资料：[设备位置服务](https://help.aliyun.com/zh/iot/user-guide/service-introduction-1)、[HTTP 定位](https://help.aliyun.com/zh/iot/user-guide/http-geolocation)、[实例概述](https://help.aliyun.com/zh/iot/user-guide/overview-60)、[计费概述](https://help.aliyun.com/zh/iot/product-overview/billing-overview)。

## 2026-11-19 定位日志隐私发现
- 只读检查发现既有物联网平台运行日志包含辅助定位返回的坐标字段，并记录 GeoLocation 物模型属性不存在的校验错误；不在工件中记录位置值。控制台显示云端运行日志转储正在运行，尚未核实该条日志是否进入 SLS。
- 停止转储只会阻止新日志导出到 SLS，不能证明物联网平台不生成坐标日志，也不能删除已有日志。按用户选择先只读排查，暂停新定位请求与实机 MQTT 上报，不修改云资源、日志设置或账单。
- 位置曾出现在浏览器工具的本轮原始输出中，不再次读取、转述或复制；该事实应对用户如实说明。单条坐标日志不证明完整位置 payload 持久化。
- 用户后续说明：如果只读排查无法找到阻止写入的方法，接受坐标进入受控日志；仍不得在工具输出或回复中复制坐标、凭据。已查看现有日志界面和官方文档，未找到按坐标字段阻止 IoT 运行日志产生的设置；关闭 SLS 转储不等于关闭 IoT 源头日志。未修改设置或删除日志。
- 2026-11-19 03:21（北京时间）云端运行日志同一设备的相邻事件包括辅助定位请求成功和 MQTT user/update 上行成功（QoS 0）；SLS 查询同一时刻出现上行及 Topic 相关记录。未读取完整 MQTT payload，不能声称原始位置 JSON 持久化。
- 用户随后确认设备配置保存及读回校验成功；单独按 RST 后，设备报告加载配置、Wi-Fi 已连接和阿里云 MQTT 已连接。
- 用户随后确认重启后新一次 Wi-Fi 估算位置已由设备端发送；2026-11-19 03:43:22（北京时间）物联网平台运行日志显示该次定位请求和 user/update 上行成功，SLS 出现同一时刻上行和 Topic 记录。只核对时间、状态、Topic，不记录坐标或凭据；完整 payload 长期保存和多地点精度仍未验证。

## 2026-11-19 高德服务只读调查
- 高德 FAQ 称智能硬件定位仅向企业开发者开放；公开价格表中未认证及个人认证账户该项配额为 0。当前浏览器未登录高德开放平台，无法核对本人的高德账号、认证类型或实际权限。
- 官方价格表列非商业条件下合格的企业认证开发者 5,000 次/月（对应免费权益期和资格须以平台核准为准），技术服务许可的企业认证开发者列 9,000,000 次/月；公开价格列 30 元/万次、无折扣。不要把更便宜的“基础地图定位服务”价格当作硬件定位价格。商业许可、其他费用及失败调用的计费范围仍需核实。
- 2.0 文档支持 HTTPS POST，Wi-Fi 接入时已连接 Wi-Fi 的信息为必填；可提交不少于 2 且少于 30 个固定接入点观测，返回精度半径。正式请求会向高德传递接入点标识、信号等敏感观测，必须先明确服务和用户授权。
- 设备现有 `wifi location scan` 只计数并清除本地观测，不保留或上传标识、信号，也没有可调用的密钥；实际覆盖和室内精度未验证。Wi-Fi 观察数 3 并不证明能匹配高德数据库。
