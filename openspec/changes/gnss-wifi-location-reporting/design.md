# Design

## Context
ESP32 Wi-Fi 固件使用 CA 校验 TLS 和 RAM 凭据。BC20 官方库以全局结构返回 RMC、GGA、GSA，读取返回值不足以证明内容有效。

## Goals / Non-Goals
**Goals:** 获取可判定质量和时效的单次定位，并复用 MQTT 发布。
**Non-Goals:** 蜂窝联网、休眠、显示或云位置存储。

## Decisions
- 独立 GnssProvider 拥有生命周期及结果；每次尝试先失效旧结果，逐次清空官方全局结构并校验数据，避免失败时复用旧值。
- 限时 180 秒，3D、GGA 质量非零、RMC A、有效 UTC、坐标、HDOP 大于 0 且不超过 2.5、至少四颗使用卫星；结果采集后 120 秒过期；本次尝试中两次合格 RMC UTC 必须递增，以拒绝重复旧历元。RMC 与 GGA UTC 相差不超过 5 秒以避免混用不同历元。
- 成功或失败均请求 QGNSSC 关闭，并查询确认；无法确认时明确显示未知，不将其当作已关闭。
- 复用 TLS 和时间回退，移除可绕过定位质量门槛的手动坐标发布命令。位置 JSON 不记录到日志，板包 MQTT 客户端的 1024 字节缓冲区可容纳该消息。
- 官方示例仅作为人工诊断参考：读取并检查示例后，在用户接天线并室外就绪后才能烧录运行；示例会开启 GNSS，退出需断电或关闭。

## Risks / Trade-offs
- [官方库解析对错误响应不健壮] → 项目内保留官方库副本并增加空响应和无效电源状态保护，仍须在实机验证全部异常路径。
- [GNSS 与天线无法通过软件可靠区分] → 超时报错列出天线及环境原因。
- [SLS 日志未证明 payload 持久化] → 原始 payload 存储需另行设计及授权。

## Migration Plan
烧录会替换固件；保留原始构建产物用于同方式回刷。先关闭串口监视器，重新枚举端口，低速分段写入并逐段校验。失败时重新插拔 USB，SET + RST 不是下载模式。
