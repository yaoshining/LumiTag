# 固件

`LumiTagWiFi` 是当前原型的 Wi-Fi 与阿里云物联网平台连通性草图。它用于在 NB-IoT 卡恢复前完成局域网接入、云端接口和位置上报流程的开发。

## 烧录

在 Arduino IDE 1.8.x 中打开 `LumiTagWiFi/LumiTagWiFi.ino`，选择：

* 开发板：`TinkerNode NB-IoT (CH)`
* 端口：本开发板实际使用的 ESP32 USB 串口，例如 macOS 下的 `/dev/cu.usbserial-*`

烧录后打开串口监视器，设置为 `115200` 波特率和 `Newline` 行结束符。

## 串口命令

* `scan`：扫描附近的 Wi-Fi 网络。
* `ssid <网络名称>`：设置 SSID。
* `password <密码>`：设置密码。
* `connect`：发起连接，最长等待 20 秒。
* `status`：显示连接状态和信号强度，不输出网络名称或 IP 地址。
* `disconnect`：断开当前连接。
* `config save`：将当前完整 Wi-Fi 和云设备配置保存到设备 NVS，并读回验证。
* `help`：显示命令说明。

## 阿里云 MQTT

已在阿里云物联网平台的华东 2（上海）公共实例创建 `LumiTag` 产品和 `LumiTag_ESP32_01` 原型设备。固件使用产品预置、具备发布权限的 `user/update` 自定义 Topic，无需额外创建 Topic。

从设备详情的“设备证书”获取 `ProductKey`、`DeviceName` 和 `DeviceSecret` 后，在串口监视器依次输入：

```text
cloud product <ProductKey>
cloud device LumiTag_ESP32_01
cloud secret <DeviceSecret>
cloud probe
gnss fix
cloud connect
cloud location gnss
```

等待 `gnss fix` 报告合格结果后，在 120 秒内连接并发布。合格的 GNSS 位置会发布到 `/<ProductKey>/<DeviceName>/user/update`；具体字段和门槛见下文。设备密钥不会输出或提交到仓库；用户显式执行 `config save` 后会写入设备 NVS。

`cloud probe` 不会连接 MQTT 或发布数据；它会依次输出 MQTT 端点的 DNS 解析、TCP `8883` 连通性和 TLS 服务器证书校验结果，用于区分网络、证书和鉴权问题。

当前 MQTT 接入使用本公共实例的 TLS `8883` 端口。固件内置阿里云 IoT 平台用于 MQTT `8883` 的 PCA 根证书，并在连接前校时后执行服务器证书与域名校验；不会跳过 TLS 校验。根证书来自阿里云的[根证书更新说明](https://help.aliyun.com/zh/iot/user-guide/announcement-on-the-update-of-the-alibaba-cloud-iot-platform-root-certificate)。

设备会优先使用 NTP 获取 MQTT 鉴权时间。若当前 Wi-Fi 阻断 UDP/NTP，固件会使用阿里云 HTTP 时间接口作为回退来源；该 HTTP 请求只用于设置时间，不携带 Wi-Fi 密码、设备密钥或 MQTT 业务数据，最终 MQTT 会话仍使用受证书校验的 TLS。

## GNSS 原型：实现与验收状态

当前新增 `GnssProvider`，使用 DFRobot 板包 1.0.8 附带 BC20 官方库的项目内副本，针对空响应和无效电源状态增加保护；这些修改仍须实机验证。串口命令：

* `gnss status`：显示电源、最近结果和本次尝试的最后一份诊断采样及其年龄；`unknown` 表示不能确认电源状态。
* `gnss fix`：清除旧结果，发起最长 180 秒的单次定位，并周期输出 RMC 状态（A 有效、V 无效）、GGA 质量、GSA 定位模式（1 无定位、2 为 2D、3 为 3D）、GGA 已用卫星数和 HDOP；`unavailable` 表示字段缺失或无效，读取失败会单独标记。已用卫星数并非 GSV 可见卫星数；读取状态 `ok` 只表示库调用返回成功，不代表字段完整或定位有效；BC20 串行请求可能使超时处理延后数秒。成功、超时和启动失败均尝试关闭 GNSS，关闭不能确认时明确警告。
* `cloud location gnss`：仅在 MQTT 已连接且最近成功定位不超过 120 秒时发布；失败尝试立即使旧定位失效。

质量门槛：本次尝试中两次合格定位的 UTC 必须递增，RMC 有效、GGA 有效质量、GSA 3D、RMC/GGA 合法且相近的坐标和不超过 5 秒的时间差、有效 UTC 日期时间、HDOP 大于 0 且不超过 2.5、GGA 至少 4 颗已使用卫星。海拔、速度和航向必须完整且有效；静止时若模块不提供航向则不会发布。输出包含 `latitude`、`longitude`、`altitudeM`、`speedKmh`、`headingDeg`、`capturedAtUtc`、`fixMode`、`satellitesUsed`、`hdop` 和 `source`；坐标会显示在本地串口，避免分享串口输出中的敏感位置。

定位期间每约 15 秒读取一次 GSV：`visible-by-system` 是各 NMEA 星座报文声明的可见数量，`parsed-satellites` 是收到并解析的条目数；多星座或多信号的统计可能重复，不能把各系统数量简单相加当作去重后的总数。`GSV satellite` 输出卫星编号和 `C/N0`（dB-Hz）；`unavailable` 代表无有效信号数值，数值 0 是报文原值，不代表已获得可用信号。`complete` 仅表示本次已接收到已报告的全部分片并通过校验，不保证所有星座都上报；`incomplete` 或 `unavailable` 不等于零颗可见卫星。`gnss status` 显示最后一次 GSV 摘要和年龄。

可用信号、天线位置、遮挡、供电及模块行为都会影响结果；只凭室内一次测量不能确定天线损坏。应在相同设备和供电条件下比较室内、窗边及室外开阔处的数据。

### 官方示例硬件诊断方案

先断电确认有源天线连接板背面 `GNSS` 接口，到室外并将陶瓷面朝天空。检查板包官方 `GNSS/getRMC`、`getGGA`、`getGSA` 示例：它们会开机并打开 GNSS、持续查询，属于会改变模块电源状态的诊断，不是纯只读操作；运行示例还需要替换现有固件，先准备回刷文件并告知操作者。分别观察 RMC 的 A 状态与坐标时间、GGA 的质量/卫星/HDOP、GSA 的 3D；不能仅凭代码或串口启动信息判断天线和定位成功。结束后关闭 GNSS 或断电，并恢复 LumiTag 固件。室外条件不具备时不要宣称验收通过。

### 验收与数据边界

源码及本地编译、实际烧录和逐段 Hash、室外实机定位、TLS MQTT 发布、IoT/SLS 发布行为及完整 payload 长期存储分别验收。以往 SLS 运行日志仅证明上行发布行为，不能证明保存了完整位置 JSON。若后续需要存储原始 payload，可设计 IoT 规则转发到受控存储、制定保留期和访问控制，评估费用后另行请求授权；当前不创建任何云资源。

## Wi-Fi 辅助定位准备（尚未完成）

`wifi location scan` 仅在设备本地统计扫描到的网络数和不同单播接入点数；不打印 SSID 或 BSSID、不向云端发送指纹，扫描结束后清除驱动结果与临时标识。这个数量没有排除移动热点或确认数据库覆盖，不能证明可以定位。扫描实现已编译；实际部署与运行情况应以本轮设备验证为准。

`cloud location wifi probe` 是一次性的阿里云设备位置服务诊断：先在 RAM 配置 Wi-Fi 和现有设备身份并连接 Wi-Fi，再由设备扫描附近热点，通过校验证书的 HTTPS 上报至阿里云；串口只显示数量与状态码，不打印热点、Token 或坐标。服务端可能写入设备位置属性，现有 LumiTag 产品尚未配置文档要求的 GeoLocation 物模型，失败不能单独证明权限不存在。该诊断不发布位置到 MQTT；返回不含可验证的精度半径，不能作为合格位置。无法自动识别移动热点，请尽量关闭附近移动热点；实际定位权限和覆盖均须实测。

`cloud location wifi private` 执行同样的一次请求，并仅在本机串口显示本次返回的坐标，以便用户自行比较实际位置；不得保存或转发串口输出。坐标系代码 2 为 GCJ-02，应使用相同坐标系的参考位置比较。坐标不写入设备 Flash、不输出至固件日志、不发布 MQTT；服务端仍可能保存位置属性。不要把本机显示的坐标或参考地址发到聊天。误差应由用户根据本地对照估计，设备没有返回精度半径。

`cloud location wifi` 在 MQTT 已连接时发起一次新的 Wi-Fi 定位，并仅在坐标合法、坐标系为 WGS-84 或 GCJ-02、UTC 有效且自本次扫描开始不超过 60 秒时，发送至现有 `/<ProductKey>/<DeviceName>/user/update`。JSON 含 `latitude`、`longitude`、`capturedAtUtc`、`source:"wifi"`、`coordinateSystem`、`accuracyM:null`、`accuracyStatus:"unknown"` 和 `estimate:true`。这是精度未知的估算位置；定位失败、过期或 MQTT 连接中断时不发布，也不复用旧坐标。上报为 MQTT QoS 0，设备“sent”状态仅说明本地发布调用成功，云端接收须另行核验。固件不打印该位置 JSON；不会创建持久化链路。

Wi-Fi 定位需要可达的定位服务把接入点观测转换为坐标；扫描不等于定位，也不提供外出时的移动网络。高德智能硬件定位提供精度半径，但官方说明仅向企业开发者开放。现有阿里云实例已通过一次设备实测返回合法 Wi-Fi 定位坐标，但准确性尚未验证；文档中的返回字段没有精度半径，不能将缺失的半径当作零。Google Geolocation 要求启用计费，其本地可达性和覆盖未验证。未来结果须明确坐标系、精度范围、来源和采集时间，不能把旧位置或 IP 估算冒充实时 Wi-Fi 定位。
